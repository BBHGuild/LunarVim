# Configuration Overview

LunarVim is designed to be fully configurable through a single entrypoint while retaining access to standard Neovim Lua APIs.

---

## Configuration Paths

By default, user configuration resides at:
- **Linux/macOS**: `~/.config/lvim/config.lua`
- **Windows**: `%LOCALAPPDATA%\lvim\config.lua`

The configuration directory structure:
```text
~/.config/lvim/
├── config.lua        # Primary configuration file
├── lazy-lock.json    # Pin file generated by Lazy.nvim
├── ftplugin/         # Buffer-specific filetype overrides (e.g. solidity.lua, python.lua)
└── luasnippets/      # Custom LuaSnip snippets
```

---

## The Global `lvim` Object

LunarVim exposes a central global table named `lvim`. Core modules inspect this table to configure behavior:

```lua
-- Change the leader key (must be set early)
lvim.leader = "space"

-- Set the active colorscheme
lvim.colorscheme = "lunar"

-- Configure built-in plugins
lvim.builtin.alpha.active = true
lvim.builtin.terminal.active = true
lvim.builtin.nvimtree.setup.view.side = "left"

-- Add community plugins
lvim.plugins = {
  { "tpope/vim-surround" },
}
```

---

## Reloading Configuration

You can reload your configuration without restarting Neovim:
1. Press `<leader>r` in normal mode.
2. Or run the `:LvimReload` command.

When reloaded, LunarVim re-evaluates `config.lua`, re-applies keybindings, and syncs Lazy.nvim plugins.

---

## Environment Variables

| Variable | Default | Purpose |
| :--- | :--- | :--- |
| `LUNARVIM_CONFIG_DIR` | `~/.config/lvim` | Path containing user `config.lua` and ftplugins |
| `LUNARVIM_RUNTIME_DIR` | `~/.local/share/lunarvim` | Path where core LunarVim files and Lazy plugins reside |
| `LUNARVIM_CACHE_DIR` | `~/.cache/lvim` | Directory for compiled cache and state files |
| `LVIM_DEV_MODE` | `nil` (unset) | When set to `1`, disables commit pinning for core plugins |
